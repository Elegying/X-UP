# X-UP 1.8.0-beta13 自动适配与检测增强

2026-11-14；versionCode 32。沿用本地 beta12 的 X 12.42 适配；未修改 X 自动更新设置，未修改 X APK。本版按 GitHub Release 测试版渠道发布，包含 beta12 的 X 12.42 修复。

## 改动

1. 匹配缓存按功能分区，并继续绑定模块版本、X 版本、基础/拆分 APK 路径、大小和修改时间；新增手动扫描代次。结构解析失败且用过缓存时，仅清理失败功能后重试一次。Hook 安装失败仍原子回滚；回滚出现异常则禁止重试，避免重复挂钩。未命中缓存、安全异常和资源耗尽不触发这种重试。
2. 结构错误区分入口缺失、候选歧义、类型/成员变化及其他初始化错误。图库的多个语义匹配路径只在零候选时回退，记住成功路径；有歧义不猜测。后续增加变体可复用这套机制。
3. 基础双击与连续点按分成独立安装事务。只有连续点按依赖基础双击，反向不依赖。检测从 10 项细分为 11 项，用户功能数量没有增加。
4. 每个 Hook 入口记录回调异常次数；累计 3 次后在当前进程放行原调用。正常 X 调用本身抛错不计入插件异常。异常报告每项每进程最多一次，并合并延迟发送；状态变化时按版本/状态组合提示一次。
5. 状态页展示各项原因和扫描/缓存/备用路径。支持手动请求下次启动全量扫描、检查插件更新及复制报告。重扫请求使用持久暂存机制，服务重连后同步，不清数据。复制的历史报告明确标为历史。
6. 报告校验 X 和插件版本、X 更新时间、扫描请求代次、启动时间及修订号，拒绝旧进程或旧快照覆盖新的异常/扫描结果。诊断仅保存功能、版本、状态与异常类型，不保存帖子或账号。

## 使用与边界

保留 X 自动更新即可。发生异常时先看“状态与帮助”；可请求重扫，再完全退出并重新打开 X。X 内部结构大改、服务器行为改变、模块自身捕获后未上报的异常、无异常的错误行为仍可能需要人工适配。运行保护仅对冒泡到 Hook 框架的回调异常有效，不能检测所有语义错误；它不能逆转回调已经造成的任意外部副作用。

未在手机上故意触发真实回调异常或升级到未知未来 X 版本；运行回退通过生产 Hook 包装器的主机故障注入验证。没有进行全部广告、翻译引擎、私信布局及长时间播放复测；沿用 beta12 已记录的验收边界。视频下载/手势内部仍共享视频基础依赖，尚非所有子功能完全独立。

没有远程下载/执行适配代码，没有自动安装插件更新。未知大改版仍需新版插件。
