# X-UP 1.8.0-beta3 审查记录

2026-10-08；版本号 22；包名、签名、模型存储及两分钟缓冲保持不变。未操作手机。

## 连续快进

旧版只改写 com.x.media.playback.v1.b 的首次双击坐标，未覆盖后续单击回调。X 12.31.0-prod.01 的 com.x.americanfootball.game.ui.d2.invoke 中，分支 a=1 通过 d 回调判断是否继续快进，未处理时回退普通单击；e 与首次双击持有同一个尺寸状态。新适配器将下半区后续点按送入同一原生向前分支，保持原生处理函数执行一次，不直接调用 seekTo、不自行创建计时器。

原生 k0.a 处理首次步长，而 x6.m 的连点分支直接读取固定 10 秒字段，绕过原有设置 Hook。本版将 PlaybackStepHook 移到共用的 x6.i 执行入口，同步调整实际增量与 Skipping 累计值，多单位重复事件按比例换算，避免 5 秒设置只对首次生效。这样连续点按显示 10→20→30 秒，或 5→10→15 秒；原生窗口结束后重新双击开始。右下重叠区域只走一次原生调用，上半区、关闭开关、缺少尺寸、其他合成类分支保持原行为。

新增测试执行生产 ContinuationTapHook 与 Hooks.intercept，用提取出的原生水平分区和活动窗口契约模拟下游：197 个断言覆盖两种步长、左下/中下/右下、连续六次、普通单击、窗口结束、上半区、关闭、缺少尺寸和其他分支。它是适配层回归，不是实机验收。

## 翻译调度与刷新

- 原来每条译文完成会通知全部缓存监听者；现在只通知该条相关监听者，避免完成内容被无关结果反复刷新。
- 客户端最多两个在途任务；名额释放后直接接续最近仍被读取的有效任务，不再依赖全页面刷新才能提交下一条。过期排队内容不自动提交。
- 定时探测仅通知未完成内容；传统 TextView 已完成后跳过定时更新，设置和上下文变化仍可触发必要更新。
- Google SDK 从每 20 ms 轮询改为直接等待完成事件，保留单句 15 秒上限与取消后的结果检查。SDK 的单句推理仍不能强制中断。
- OPUS / ML Kit 和关闭上下文时，不再查询帖子上下文索引；不因无关上下文变化刷新全部内容。
- 文本筛选的正则表达式预编译复用。模型参数、正文长度和提示词未改变，没有通过截断原文降低耗时。
- 接收结果时额外校验引擎标识，避免设置监听尚未执行时旧引擎结果回写。

## 验证

- 核心测试 629 个断言通过，其中客户端由 71 增至 92，共用步长适配器另有 25 个断言，验证首次、连续、多单位、即时设置与后退隔离；客户端新增不依赖重绘的队列接续、已完成监听者不被额外通知、过期排队不执行、切换引擎竞态。
- JVM 单元测试 42 项通过；assembleRelease、testDebugUnitTest、lintRelease 通过，Lint 0 错误、32 警告。
- 签名沿用原证书，APK 与原生库支持 16 KB 对齐，无模型权重打包。
- 未重复测量不变模型的推理性能；本轮验证的是调度和刷新行为，不声称获得某个百分比加速或满足全部帖子两秒完成。
- 待用户验证：连续点按时原生累计提示、松手后重启窗口、右下不重复跳转、快速滚动评论、前后台切换和 Google 模型运行。旧版审查列出的模型质量和其他功能验收边界仍然适用。
